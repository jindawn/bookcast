# BookCast 产品定义

BookCast 是计划开源的本地工具，帮助用户将一本书转化为高质量中文音频、精读内容或双人播客。用户可以从书名开始识别正确版本、寻找合法可获取的电子书，也可以直接提供自己的 EPUB、PDF 或 TXT，最终获得 MP3 或 M4B 音频。

Phase 8 已提供本地中文双音色 TTS，CPU 合成、逐句缓存与恢复；默认仍为 Mock 测试音调。Phase 9 增加可控推理与 DeepSeek 验收入口，真实 DeepSeek + Kokoro 链路已跑通；内容仍有来源归属警告，人工试听待完成。外部 LLM 可收费，本地 TTS 免费不代表整条链免费。Web 是 Core 的客户端，Skill/CLI 独立可用；真实人声不等于已验收内容质量。OCR、M4B、桌面包未实现。实际状态见 [STATE.json](STATE.json)。

## 用户与使用场景

Phase 10 提供可选 Gemini 云端多说话者 TTS，保留 Kokoro 本地底座。两种音频路径共用 Core；云端文本发送须显式配置，不借用 Gemini App 订阅会话或 Cookie。真实同脚本音频已生成，人工听感与免费层资格仍待确认，见 [PHASE10_TTS_AB.md](PHASE10_TTS_AB.md)。

- 希望在通勤等场景收听自己持有书籍的中文读者。
- 希望结合全书结构理解论点、概念和章节关系的精读用户。
- 希望通过双人对谈理解一本书的用户。
- 希望检查来源、替换模型或语音服务，并在本地管理书籍与输出的开发者。

## 目标流程

1. **确认书籍版本**：用户输入书名后，系统展示作品及候选版本，提供作者、语言、译者、出版社等区分信息。存在歧义时由用户确认，不能仅凭同名或文件名自动断言版本正确。
2. **获得源文件**：系统提供合法可获取的资源信息，或接受用户自己的 EPUB、PDF、TXT。没有合适资源时，明确说明并保留本地导入路径。
3. **解析整本书**：系统保留章节顺序、正文和原文位置线索，报告缺失内容、解析失败或需进一步处理的页面。不能把部分章节处理成功描述为整本书解析成功。
4. **选择输出模式**：用户选择中文音频、精读内容或双人播客。各模式应明确呈现原书内容与 AI 的解释或改编之间的区别。
5. **执行生成任务**：系统展示可理解的进度与失败原因，使用户能够定位当前处理的书籍和阶段。已完成结果立即落盘；中断后通过 Job ID 接续，永久错误修复后显式重试。
6. **导出音频产物**：完成任务后输出 MP3 或 M4B，并提供与版本、模式和章节相关的元信息；具体编码与封装策略在对应开发阶段决定。

“整本书解析”表示输入内容应被完整检查和组织，不意味着所有输出模式都逐字朗读全书。精读与播客模式可以重新组织内容，但应保留可追溯关系，避免将生成补充误当作原书观点。

## 三种内容模式

| 模式 | 用户希望获得的结果 | 质量重点 |
| --- | --- | --- |
| summary（概览） | 在预算内讲解主要结论及条件 | 覆盖透明、简洁、避免重复 |
| deep_read（精读） | 围绕全书结构、核心概念和论证展开的讲解，可进一步转为音频 | 依据明确、解释清楚、保留章节及原文线索 |
| two_host（双人播客） | 两位说话者围绕书籍展开的对谈音频 | 对谈自然、角色区分清晰、观点可追溯 |

## 产品边界

- 本地优先：书籍、书稿、任务记录和音频由用户在本地管理。是否使用外部 AI 或语音服务需由用户配置，传输内容的范围需明确。
- 合法获取：资源发现只面向合法可获取的资源，记录来源和可用的授权信息。不实现绕过付费墙、访问控制或 DRM 的能力。
- 用户输入：允许用户提供自己有权处理的书籍文件；“可以下载”或“可以上传”本身不构成权利判断。此处定义产品行为边界，不提供具体司法辖区的法律结论。
- 生成透明：不将 AI 生成内容冒充原文，不承诺书目匹配、PDF 解析、翻译或生成内容永不出错。
- 失败可见：对不支持的格式、损坏文件、缺页、扫描内容和服务故障明确报告，不能静默生成看似完整的结果。
- 范围受控：Phase 7 只增加本地客户端与应用调用层，前端不实现版权、解析、生成或恢复算法。没有账户、支付、云同步；Tauri 仅评估。无 UI 或 Skill 时 CLI 仍可用。Mock 语义复核需人工检查；预算省略的章节必须显示，不能冒称完整精读。

## 概念与关系

标准术语见 [CONTEXT.md](../CONTEXT.md)。同一 Work 可以有多个 Edition；同一 Edition 可以对应多个 SourceAsset，例如不同格式或不同来源的文件。ParsedBook 应能追溯其 SourceAsset，GenerationJob 围绕书稿与输出模式开展处理，成功的音频生成任务交付 AudioArtifact。

这些关系描述产品含义，不预设存储表、进程边界或具体实现。架构规划见 [ARCHITECTURE.md](ARCHITECTURE.md)，已经确定的约束见 [DECISIONS.md](DECISIONS.md)，分阶段验收见 [ROADMAP.md](ROADMAP.md)。
