# 决策记录

本文件是架构与工作方式的唯一决策记录入口。`accepted` 表示已确定；`deferred` 表示待选，不能写成既成事实。变更既有决策时追加原因、替代方案与影响，并将旧条目标为被取代，保留历史。禁止仅凭个人偏好推翻已确定约束。

## D-001 — 仓库承载可接力状态

状态：accepted；日期：2026-09-13。

采用 AGENTS 统一入口、短 CLAUDE 转发、架构/路线图/决策文档、HANDOFF 快照、追加式 WORKLOG 与版本化 STATE。聊天记录和某一 Agent 的私有记忆无法保证跨工具接手；重要状态必须落库。代价是每个原子任务和阶段都要维护文档、运行对应验证并小步提交。

状态：accepted；日期：2026-09-13。

原始文件、任务控制及派生产物默认在用户本地。外部书目、AI 与 TTS 能力通过适配边界接入，外发书稿需让用户知情并选择启用。这样保留本地文件工作流和供应商替换能力；并不承诺全功能离线运行，也不在本阶段锁定模型或供应商。

## D-003 — 版本可区分，来源受约束

## D-006 — 状态契约与提交证据

状态：accepted；日期：2026-09-13。

`docs/STATE.schema.json` 定义 JSON Schema Draft 2020-12 的 v1 契约，采用当前校验器支持的明确子集。字段名、类型和枚举固定；所有时间为 UTC。状态契约变化必须同步 Schema 与验证逻辑，未知关键字不得被校验器静默忽略；普通任务进度更新不修改契约。

`last_verified_commit` 只记录已存在、实际运行对应检查且通过的完整 40 位 Git 提交哈希，并且必须是当前 HEAD 的祖先（含 HEAD 自身）。尚无经过验证的提交时为 `null`。`tests.scope` 区分 `commit` 与 `working_tree`；工作区检查通过不等于已验证当前所有提交内容。

不能把“包含 STATE/HANDOFF 的提交自身哈希”写入同一次提交，否则哈希会再次改变。初始化时先提交骨架并验证，再提交包含该基础提交哈希的交接快照。快照提交后继续检查最终工作区；快照自身的最新提交使用 `git log -1 --oneline` 查询。以后同样记录最近已验证提交，禁止为追逐自引用不断 amend 或反复提交。

## D-008 — 任务按步骤原子落盘并以指纹恢复

状态：部分被 D-010 取代（Provider 指纹与配置变化策略）；日期：2026-09-13。其余原子写入、产物哈希与恢复原则仍 accepted。

## D-009 — 统一 Provider Registry 与有界故障切换

状态：accepted；日期：2026-09-13。

按本次 Phase 2 要求，以中立 Protocol 定义 LLM 的 generate/generate_structured/health_check/capabilities 与 TTS 契约。Registry 通过 kind/type 工厂注册适配器，CLI 组合注入，业务 Pipeline 禁止导入具体厂商实现。内置 Mock 和以标准库 HTTP 调用的 OpenAI-compatible/local LLM；TTS 只提供 Mock，避免本阶段引入真实语音和未被追踪的隐式子调用。

优先级通过严格 TOML 配置；默认 Mock 离线，远程端点由用户显式启用，章节与分析会发送到所选链中的服务。凭证仅用环境变量引用，服务错误只保存安全枚举；不保存原始响应错误、认证头和 Secret。local 限 loopback，远程要求 HTTPS，不跟随重定向。

只允许限流、额度耗尽、临时不可用和超时自动切换；认证、输入、schema 与业务错误停止。单次运行禁用失败实例，成功实例持续处理后续任务，无隐藏重试和隐式 Mock 回退。相比所有异常都换模型，此策略暴露程序与数据错误；代价是需要用户修复永久错误，并可能在一次显式 resume 时重新探测先前失败的服务。

外部请求成功但本地尚未持久化时无法保证远端恰好一次，resume 可能重发该未完成调用；已经完整落盘的任务不会因此重做。长期并发、预算和端点幂等键另行决策。

## D-012 — 独立获取检查点与受限下载边界

状态：accepted；日期：2026-09-14。

acquire 默认只下载/导入并解析，单独保存 acquisition.json v1；--generate 才将本地文件及来源 metadata seed 注入原 Pipeline，不更改 AI Provider 策略。重复获取复用完整哈希检查点，解析失败不重下源文件；下载中断重试整个文件，不实现 Range 续传。

Source HTTP 仅公开 HTTPS/443，不继承代理、凭证或 Cookie，不接受 query/fragment。DNS 校验后固定公网 IP 并保留原域名 TLS，每跳重定向重新验证；内容同时受大小、MIME、签名与容器校验。下载验证前不发布目标文件，不执行或展开运行内容。相比通用浏览器式下载，这会拒绝部分登录、签名链接、复杂 EPUB 和私网资源，换取可测试的明确边界。

当前网络实测会返回 198.18.* Fake-IP，因此增加显式 --resolve 主机名=公网IP，用于用户独立核验的真实地址；仍禁止私网/保留地址并验证域名证书。没有关闭 IP 防护或 TLS 的开关。首次大目录慢下载可显式调整有上限的总时限。

## D-013 — 分层内容、证据约束与显式质量门禁

状态：accepted；日期：2026-09-14。D-010 的 `pipeline_version=1` 仅继续适用于旧任务；新内容任务采用 2，调用审计原则不变；manifest 版本和配置缓存策略后由 D-014 更新。

Phase 4 按块分析九类信息，再对章节和整书做有界综合树，先持久化全局规划再生成片段、逐段一致性复核、质量报告和音频。Planner 使用确定性预算/重要性/覆盖算法，综合与写作经中立 LLM 契约，不新增厂商。所有 AI 结果和本地汇总均有检查点；Provider 切换不重做已经验证的内容。

证据以解析章节字符偏移和短引文核对，脚本按 claim ID 引用并区分作者观点、讨论与假设。私有证据不等于允许大段进入脚本，输出优先转述；产品复述阈值与检查规则不构成法律判断。质量报告区分阻断、警告和语义未验证；Mock 必须如实标为未验证。逐段 LLM 复核仍可能出错，不能替代人工质量验收。

相较整书单次摘要，这种结构增加调用与文件数量，根节点也可能遗漏细节；换取有界上下文、来源映射、预算取舍透明和最小任务恢复。字符上限、代表性压缩、精确文本去重与评估启发式详见 CONTENT，后续可以改进但不得静默丢弃底层分析。

模式和预算属于内容任务身份；同一源文件比较不同方案使用不同输出目录。旧任务不静默升级、重算或伪造质量记录。显式片段修订增加持久化修订号，保留分析与规划，并让上下文变化传播至受影响下游；没有自动换模型或无限改写循环。

## D-014 — 持久化任务、内核锁恢复与可核验缓存

状态：accepted；日期：2026-09-14。局部取代 D-010 的 manifest v2、忽略全部 Provider 配置变化及恢复入口策略。

Phase 5 继续使用本地 JSON 和原子文件写入，不引入数据库或后台调度。manifest v3 对应 Job，包含独立随机 job_id、Step、Artifact、Attempt、来源路径/metadata seed、Provider 无密钥配置快照与运行所有者。旧 status/error_kind 保持兼容，计算出的 state 统一为六态；读取忽略外部写入的 state，避免矛盾的双状态源。旧 v1/v2 原样备份并保留 pipeline_version，缺失历史不伪造。

运行以 OS 内核独占文件锁为准。只有成功持锁后才将旧 RUNNING/pending 调用标为 interrupted 并恢复；PID、主机、时间仅用于诊断，不使用 TTL 抢占，防止慢请求被另一进程重复执行。CLI 按 Job ID 或目录定位，优先校验导入副本，缺失时校验原路径；保存来源 seed 以保持获取身份。resume 不重试永久错误，修复后由 retry 显式重试；兼容入口 generate --resume 保留既有显式重试语义。

Artifact 的 cache_key 覆盖 input_hash、prompt_version、provider_config_hash，并校验文件 SHA-256。Provider 摘要由实际实例的 name/model/cache_key 哈希而来，不保存 Secret。同名实例仍在所选链中但配置改变时，其完成 AI 检查点失效；实例被移除或显式换成其他 Provider 时，继续复用输入及产物有效的旧结果并保留来源。这样兼顾配置改动的可见性与第七章额度耗尽时保留前六章。旧调用没有配置摘要时使用原输入/产物校验，不编造来源。整本采用新模型仍建议新输出目录。

恢复默认使用保存的配置，不隐式读取新工作目录的 TOML。显式 --config 可以覆盖快照；没有快照的旧非默认任务要求显式提供配置。每次 AI 调用前/后和每步状态变化立即保存；已完成 Attempt 可修复 Step 的提交间隙。计划变化后不再需要的步骤标为 SKIPPED，保留历史和文件。

任务清单按阶段登记，规划前明确显示已知剩余量而非虚构总量。日志追加至 JSONL，状态查询只读；日志写入或终端断开不得让持久化成功回退。内核锁和原子替换的代价是限定本机文件系统语义；网络共享盘/多主机并发未验收。操作系统重启后需手动 resume。远端已处理而本地尚未保存的请求仍无法保证恰好一次或免重复计费。

## D-015 — 本地同源客户端与独立 worker

状态：accepted；日期：2026-09-15。扩展 D-014 的客户端执行方式，不修改 Core Job、缓存与恢复语义。

Next.js 只静态导出页面，FastAPI 在 127.0.0.1 同源提供。Application API 原子保存带幂等 ID 的提交，再派发独立 Python worker，复用 Acquirer、Pipeline 和 CLI 共用配置组合。静态页面减少常驻 Node 进程；持久化提交与独立 worker 避免 API 关闭时丢失尚未创建的 Core Job。

提交记录不保存 AI 步骤状态；Core manifest 存在后，进度、错误、缓存与完整性以 Core 为准。每个新提交有独立 output 根，支持同一本书比较模式；相同幂等 ID 不重复创建。默认 data/web 与旧 CLI output 分离，代价是 UI 历史暂不导入旧 CLI 任务，多次主动新建会有独立缓存。每工作空间最多两个活动 Web worker，超额提交保留，稍后手动恢复，不引入自动队列。

入口绑定 loopback，校验 Host/Origin/Fetch-Site；浏览器不能提交任意服务器路径、URL 或凭证。上传有界落盘后复用 Core 验证；固定音频路径只服务完整性有效的完成任务。Tauri 暂不实施，后续可复用静态客户端并打包 Python/FFmpeg sidecar；跨平台分发、签名、端口和进程生命周期需要独立验收。

## D-016 — 可选本地人声与 Core 逐句检查点

状态：accepted；日期：2026-09-15。扩展 D-014/D-015，保留 manifest v3 与旧整段任务。

用户要求免费开源和中文友好优先。首个真实 TTS 使用 Kokoro 多语言模型，经 sherpa-onnx CPU 运行，模型在显式 setup 时下载及验证，生成不联网。适配器与依赖均可选，默认 Mock 不发生意外下载或费用。较重的 GPU/声音克隆方案与付费平台暂缓；代价是需要本地模型存储、CPU 时间以及人工发音验收，不能把免费使用等同于所有组件许可相同。

新增能力协商 speech_units 和中立 SpeechUnit/SpeechInfo；Core 以至多80字符保存每次语音推理，沿用 Step/Artifact/Attempt 与锁恢复。Adapter 只负责一次合成，Core 负责分割、缓存和拼接，避免适配器内出现不可观察的长任务。纯 Mock 保留整段接口。句间固定间隔与硬长度边界优先满足恢复和上下文上限，细腻语调衔接留待试听优化。

模型/词典实际哈希、运行时版本、音色、语速、线程进入 Provider cache_key；安装绝对路径只用于定位，不改变相同内容的缓存身份。开始一次运行验证资产后复用内存摘要，运行期间不可修改模型文件。旧 Provider 被替换时，仍按 D-014 保留有效完成音频，不静默重新生成；整本改成人声选新输出目录。导出和客户端使用实际音频类型与时长，LLM 的 Mock/语义质量状态独立保留。

## D-020 — M4B 是已完成音频的独立导出

状态：accepted；日期：2026-09-23。Phase 13 不修改 LLM/TTS 任务与 manifest，也不改变既有 MP3。用户显式调用 `bookcast export JOB_ID --format m4b`；独立 export 模块持同一 Job 锁，读取已完成 MP3、真实章节 WAV、元数据与节目规划，以 FFmpeg 编 AAC/M4B 并写 sidecar。新分层任务用 podcast segment 作章节并保留源书章节 ID 映射；无 episode plan 的旧任务才用 source chapter。章节起止由 WAV 实际帧长与最终 MP3 实测时长确定，禁止用预算或字数估算。封面仅用户显式提供可解码、大小受限的本地 JPEG/PNG。输入哈希含 MP3、WAV、规划、元数据、封面及编码契约；输出 SHA 校验后复用，Web 只暴露有效现存 M4B。这样避免重新消耗 AI 额度；代价是完成 Job 不会自动有 M4B，需用户显式导出，变更源音频后需重导出。
